# 电脑端 RS485 报文监视器

入口：桌面 **PowerScope RS485** 快捷方式，或双击 `tools/start_rs485_monitor.cmd`。本机页面为 <http://127.0.0.1:18766/>。它直接打开电脑 USB-RS485 串口，读取 FPGA 的 Modbus 应答；所有接收字段来自实际字节。

页面上方已加入 [完整演示](QUICKSTART.md)：网口发送真实电流窗口，手动注入 / 恢复，或 21 秒自动场景；下方串口接收功能保持独立可用。

## 使用

1. USB-RS485 插入电脑，板端 A0/B0 已连接。页面默认选择本次确认的 CH340 **COM22**；适配器端口改变时，点击“刷新”并选择实际端口。
2. 点击“开始接收”。固定使用 **115200、8E1、从站 1、功能 03、寄存器 0–9**，默认每 100 ms 查询一次。当前 PL 是 Modbus 从站，电脑发送只读查询后才有应答。
3. 左侧显示 TX 请求、RX 原始报文、电脑时间和 CRC。点击一条报文，右侧显示字节分组、故障类型、结果序号、模型分数、NPU 耗时及 10 个寄存器的十六进制/十进制值。
4. “仅接收”过滤 TX；“异常”显示损坏报文、超时、应用错误及查询前遗留字节。“跟随最新”控制自动滚动；选中历史报文时停止跟随，右侧保持该条报文供核对。
5. CSV / JSONL 导出完整当前会话，不受页面只显示最近 100 条事务的限制。“清空显示”仅清理页面历史，继续接收并保留完整文件。
6. 点击“断开”释放串口，当前结果与导出仍可查看；“退出程序”先关闭串口，再退出本机服务。关闭网页标签页不会停止已启动的串口接收，重新打开页面可继续查看。

桌面快捷方式启动隐藏的本机服务并打开浏览器；重复双击会复用同一服务。服务只监听本机回环地址，不需要板端 SSH 或网络。原诊断网页仍是 <http://127.0.0.1:18765/>；在该页面启动监测、注入故障时，电脑端串口页面会显示相应的实际应答。

## 状态含义

- **有效报文**：CRC、地址、功能、寄存器数量及 ABI 字段符合协议，可能包含待机结果。
- **正常 / 故障**：结果 VALID 为 1，页面显示收到的类别。正常类别为 0，开关开路为 1–12，传感器断线/卡死/偏移为 13–21。
- **板端待机 / 暂无有效诊断**：通信正常，但 VALID 为 0、类别 FFFF。板端尚未开始监测或已停止时会出现这一状态。
- **应用错误 / 结果发布超时**：从寄存器 error 字段显示 NPU、存储、AXI、输入或 500 ms 发布超时状态。
- **CRC 错误 / 超时 / 不支持的 ABI**：原始报文保留，页面不将其解释为有效诊断。后端异常或 USB 断开会显示连接中断并释放串口。

“模型分数”是寄存器值除以 10000 的分类分数，不是整体准确率；NPU 标志位表示设备协议中声明已执行 NPU，RS485 ABI 1 本身不携带 PS 规则来源字段。“结果更新”按有效帧序号变化计数，轮询同一帧不重复增加。

## 文件位置

- 程序：`pc_monitor/`，Python 标准库 HTTP 服务、pyserial 桥接、静态 HTML/CSS/JavaScript。
- 原始记录：`artifacts/pc-rs485-monitor/captures/<UTC时间>-<会话编号>.jsonl` 和 `.csv`。每条包含原始请求、应答、CRC、解析状态与单调时钟时间。
- 服务日志：`artifacts/pc-rs485-monitor/server.stdout.log` / `server.stderr.log`。
- 本轮截图与下载证据：`artifacts/pc-rs485-monitor-20261101/output/playwright/`。

电脑已使用 `C:/Python314` 的 Python 与 pyserial 3.5。换电脑时安装 Python 和 `requirements-pl.txt`；启动器会探测已安装且可导入 pyserial 的 Python。也可从仓库根目录运行 `python -m pc_monitor`。前端资源全部在本地，不依赖 CDN。

## 本轮验证

16 项协议、串口生命周期、错误处理、会话导出和 HTTP 控制检查通过。验证包括已有 22 类及待机/错误向量、CRC 损坏、部分读取、USB 断开、未知 ABI、重复连接、接收过程中导出完整记录，以及旧会话导出拒绝。

浏览器完成真实 COM22 接收、字段检查、筛选、点击历史报文、CSV/JSONL 下载、桌面和窄屏布局检查，无脚本错误。复用当时已经打开的接收会话，在 DR1 上进行约 3 秒短运行：正常、Ta2 开路、A 相卡死、恢复正常。41 个板端窗口中，PC 100 ms 轮询取得 28 个有效诊断快照，与对应板端记录的全部 10 个寄存器逐字段一致；导出的 1079 次查询中 CRC、超时和协议错误均为 0。完整统计与哈希见 `reports/pc-rs485-monitor-20261101.json`。

本轮只新增电脑端程序。板端仍使用 c8cbe58 事件监测服务、sfaug-r1 纯 NPU 和 236df82 FPGA 位流。此前提交材料包保留原样，电脑端另有独立软件包可作为演示配套。
